# Changelog

Protocol changes (prompts, cities, engines, metrics, thresholds) open a new
protocol version and must be recorded here with a reason (PROTOCOL.md section 6).
Code-only changes are recorded as patch versions.

## v0.1.1 — 2026-11-12 (before first wave)
- Claude engine model: claude-opus-5-5 → claude-sonnet-5-5 (closer to what most consumer-app users get; lower cost).
- Perplexity mode: chat_completions → agent (Sonar chat-completions support ended 2026-09-27 per Perplexity docs).
- Gemini parser: live API returns opaque `vertexaisearch…/grounding-api-redirect/…` citation URIs; the source domain is taken from `groundingChunks[].web.title` (original redirects kept in `extra.grounding_redirects`). Found in the first live smoke test.
- Note: requesting `gemini-3.5-flash` returned `gemini-3.6-flash` in the live smoke test (Google-side aliasing). Both strings are logged per protocol §3.3.
- Note: Perplexity agent mode with model `sonar` returned `openai/gpt-6-luna` in the live smoke test — the answer is generated by a third-party model selected by Perplexity's preset, on top of Perplexity's search. Reports must describe the Perplexity engine as "Perplexity search + preset-selected model" and log the returned model per wave.

## v0.1.2 — 2026-11-12 (after pilot `pilot-2026-11`: roofing × Houston, Denver, Boise, Knoxville, Bend)
- collect: `--niches` filter for pilot runs.
- resolve: website check only when the stated value is a URL/domain; address check only when a house number is stated (house number + street word must match). Pilot showed false positives from city-only addresses and business names in the website field.
- Phone mismatch is no longer counted as a fact error. It is reported as "phone differs from Google profile", because many businesses list a call-tracking number on Google. Verifying whether the AI-stated number is a real number of the business is an open item before wave 1.
- metrics: sponsored local-pack slots (`is_paid`) are excluded from pack overlap.

## v0.1.3 — 2026-11-12 (verification step, pilot)
- New `panel.verify` (run after `panel.resolve`, before `panel.metrics`):
  - Phones: for each AI-stated phone that differs from the Google profile, fetch the business's own site (home page, exact profile URL without tracking params, first contact page; cached in `data/cache/sites/`) and label `phone_check` = site_match / site_no_match / site_unavailable.
  - Unresolved mentions get `unresolved_reason` (same_name_outside_metro / low_name_similarity) from cached Places results; no new API calls.
  - Manual/web-search verification files in `data/manual/<wave>/` (`unresolved_verified.csv`, `phones_verified.csv`) are merged: `ghost_manual_check` label, `is_ghost` = 1 only for `not_found`; `phone_check` = `manual_<label>` for automated non-matches.
- Pilot results of the manual step (web search per business/number, evidence URLs in the files): 76 distinct unresolved names → 45 found_local (Places missed trade-name variants and suburbs), 9 found_elsewhere, 22 not_found. 45 phone rows → 10 belongs_to_business, 2 belongs_to_other, 1 old_number, 32 unverified.
- Known limit: automated site check misses numbers rendered by JavaScript or written as letters (e.g. 346-ROOF); these fall to the manual step.

## Protocol v0.2 — 2026-11-12 (before first full wave)
- Niches: roofing / hvac / plumbing → **construction (general contractor), appliance_repair, roofing, cleaning (house cleaning)**. Reason: these are the niches the author's agency serves, so findings can be checked against client work and used in practice. Roofing prompts unchanged, so the November pilot stays comparable for roofing.
- Volume per wave: 12 templates × 20 cities × 5 engines × 5 repeats = 6,000 AI responses + 240 local-pack pulls. Estimated cost ≈ $190/wave (pilot cost scaled).
- Extractor prompt v2 (`extract/prompt_v2.txt`): only the niche examples in the first sentence changed; schema v2 = v1.
- HVAC and plumbing templates stay in `config/panel.json` for one-off checks outside the panel, but are not part of the panel waves.
- `panel.collect --repeats N` (smoke tests only; waves use protocol k). Smoke test `smoke-niches-2026-11`: Houston × construction / appliance_repair / cleaning × k=1 → 45 AI answers, all engines OK (2 DataForSEO 40101 errors retried). Unresolved rate 27% (pilot roofing: 11%), mostly small service-area businesses and franchise name variants → consider a second Places query with the niche keyword before the full wave.
- Resolution (protocol 4.4, v0.2): if `name + city` finds no match, a second Places query `cleaned name + niche keyword + city` is tried (`resolution.niche_keywords` in config; location suffixes in brackets/after a dash removed). Names equal after removing spaces, punctuation and legal suffixes count as a match ("ResCom" = "Res Com"). Same similarity threshold and metro radius. Smoke wave: unresolved 27.0% → 24.1% (43 extra Places calls). The remaining unresolved names mostly return no Google listing at all.
- **Bug fix (resolution):** Places Text Search excludes pure service-area businesses (no public address) unless `includePureServiceAreaBusinesses` is set. Most cleaners and appliance-repair firms and many roofers are such businesses. Now set (`places.include_pure_service_area_businesses`). Found by manual spot check of an unresolved business (Budget Buddy Appliance Repair, Houston). Because these listings have no coordinates, the metro-radius check is replaced for them by a phone area-code check (`panel/areacodes.py`; toll-free/missing phone → not matched). Earlier matches with coordinates are kept from the old cache; only failures were re-queried.
- Effect: pilot unresolved 9.5% → 4.6%; smoke (new niches) 27% → 8%. 13 of 22 pilot names that web search had labeled `not_found` are real Google listings in the metro (often the AI-stated phone matches), so the earlier pilot ghost estimate was too high; web-search-only "not found" is not reliable for service-area businesses.
- **Protocol v0.2, section 4.6 (sample-based manual check):** each wave, a random sample of 50 unique unresolved (name, city) pairs per niche (seed = wave id; earlier labels reused) is checked by hand; ghost rate = unresolved share × mention-weighted `not_found` share, with bootstrap 95% CI; "wrong city" estimated the same way. Reason: at full scale (~700 unique unresolved names per wave) checking every name is not feasible. Implemented in `panel.verify --sample` (writes `data/manual/<wave>/unresolved_sample.csv`) and `ghost_estimate.csv`. Section 4.4 rewritten with the v0.2 resolution rules; 4.5 fact error excludes phone (reported separately).
- Pilot after all fixes: ghost rate (roofing, all engines) 0.8% [0.3%, 1.5%]; wrong city 1.4% [0.5%, 2.4%].
